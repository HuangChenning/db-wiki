# 刷新物化视图

#### 说明

刷新物化视图也会自动更新其所有索引。

#### 注意

- 增量刷新（`REFRESH FAST`）利用物化视图日志中的记录信息来确定需要增量刷新的内容，OceanBase 集中式数据库支持物化视图日志自动管理功能，系统默认自动创建对应的 mlog 或更新已存在的 mlog 表定义使其包含新建物化视图依赖的列，详细信息参见 [物化视图日志](200-materialized-views-log-of-oracle-mode.md) 下自动管理物化视图日志章节。
- 本文的示例都使用物化视图日志自动管理功能，如果需要手动创建物化视图日志，手动创建物化视图日志详细信息，参见 [物化视图日志](200-materialized-views-log-of-oracle-mode.md) 下手动管理物化视图日志章节。
- 对于 V4.4.2 版本，从 V4.4.2 BP2 版本开始支持在创建增量刷新物化视图时，如果物化视图定义有聚合函数或 `UNION ALL` 算子时，无需手动指定对应依赖列。

#### 说明

由于嵌套物化视图不支持实时物化视图，所以在 `FROM` 表为物化视图时，无法使用实时物化视图。

#### 注意

使用 `MIN`/`MAX` 函数的物化视图不支持实时物化视图。

#### 说明

OceanBase 集中式数据库 `MIN`/`MAX` 聚合函数参数支持非基本列，`GROUP BY` 列中支持使用非基本列。

#### 注意

- OceanBase 集中式数据库物化视图的增量刷新功能支持多表外连接（`LEFT JOIN`/`RIGHT JOIN`）。
- 外连接使用限制：连接树需要是等价于 `INNER JOIN` 在先，`LEFT JOIN` 在后的左深连接树。
- 若增量刷新物化视图的 `SELECT` 子句包含 `LEFT JOIN` 算子，则禁止在创建时指定主键（`PRIMARY KEY`）或唯一索引（`UNIQUE INDEX`），以避免因约束冲突引发的刷新异常。
- 带有外连接的聚合物化视图不支持实时物化视图。

#### 说明

- 为了使简单连接物化视图在增量刷新和实时物化视图中获得较好的性能，推荐按照以下方式为物化视图及其依赖基表创建索引：
  1.  为每张表的连接键创建索引，用于提升增量更新和实时物化视图中表的连接性能。
  2.  为物化视图中各基表主键列创建索引。
- 随着物化视图中 `JOIN` 表数量的增加，物化视图的增量刷新性能和实时物化视图查询性能通常会有所下降。

#### 说明

视图 `DBA_MVIEWS` 查看物化视图并行度只能查看针对物化视图指定的的并行度。

- 字段 `REFRESH_DOP` 为非 0 时，物化视图后台刷新任务将使用 `REFRESH_DOP` 对应的并行度。
- 当 `REFRESH_DOP` 为 0 时，将使用设置 Global（全局）级别的 `mview_refresh_dop` 的值。

#### 注意

设置 Global 级别的变量对当前 Session 无效，需要重新登录建立新的 Session 才会生效。

#### 说明

物化视图的所有者和租户管理员用户才可以执行刷新操作。

#### 说明

对于 V4.4.2 版本，该参数从 V4.4.2 BP2 版本开始引入。

#### 注意

如果未显式指定并行度，且 `mview_refresh_dop` 变量为 0 或 1 时，不开启并行刷新。

#### 说明

下述并行度优先级依次降低。

#### 注意

如果创建物化视图时未显式指定并行度，且 `mview_refresh_dop` 变量为 0 或 1 时，后台刷新任务不开启并行刷新。

#### 说明

OceanBase 集中式数据库支持基于无主键的物化视图创建嵌套物化视图。

#### 注意

嵌套物化视图不支持创建为实时物化视图，即创建嵌套物化视图时不支持指定 `ENABLE ON QUERY COMPUTATION` 子句。

#### 注意

由于 `mv1` 经历过全量刷新，因此直接对 `mv2` 进行增量刷新会报错，必须先进行一次全量刷新。
