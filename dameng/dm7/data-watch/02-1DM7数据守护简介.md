`DM7`数据守护（`Data Watch`）是达梦数据库`DM7`版本新推出的一种集成化的高可靠性解决方案。通过为主机配置一个或若干个备机，将主机生成的归档日志发送给备机进行重做，实现主备机的数据一致。当主机发生故障时，备机能切换为主机继续对外提供服务。

`DM7`数据守护能同时满足用户对数据安全性和系统高可用性的要求。解决由于硬件故障、自然灾害等原因导致的数据库服务长时间中断问题，满足用户不间断提供数据库服务的要求。

部署`DM7`数据守护系统，您可以获得以下收益：

- 高可靠性：最佳的数据保护性和系统可用性。备数据库与主数据库的数据一致，且备数据库可在数秒内转换为主数据库；
- 低实施成本：成熟的功能和丰富的管理接口，具有`DM7`企业版的所有功能与特性，无需额外购买组件；
- 高投资回报：备数据库可同时用于查询操作的生产目的，在不增加复杂度的前提下，充分利用和平衡系统资源。

## 1.1 系统架构与原理概述

`DM7`数据守护包含的主要部件有：主数据库、备数据库、异步备数据库（最多8个）、联机`REDO`日志系统、本地`REDO`日志归档服务、实时`REDO`日志归档服务、`REDO`日志重做服务、`MAL`系统、守护进程（`dmwatch`）和监视器（`DMWMON`）。其中，守护进程和监视器是两个独立的工具，其他部件集成在`DM7`数据库服务器`DMSERVER`中。`DM7`数据守护的系统架构如图`1.1`所示。

`DM7`数据守护的实现基础是`REDO`日志的生成、归档、传输和重做。数据库对象的任何修改都可以归结为对数据页的改动，`REDO`日志忠实地记录了数据页内容的变动情况。且`REDO`日志具有原子性、有序性的特征，每条`REDO`日志记录包含明确的操作内容，并且`REDO`日志是严格按照操作的先后顺序生成的。借助`DM7`的`REDO`日志归档机制，将主数据库产生的`REDO`日志，通过网络传递到备数据库，备数据库的`REDO`日志重做服务解析并重做`REDO`日志，在对应数据页的对应偏移上写入最新数据，从而实现了备数据库与主数据库之间的数据同步。这种同步是纯粹物理层面的同步，可以严格保证主、备数据库之间数据是完全一致的。

`REDO`日志由一系列的`REDO`日志记录`RREC`组成，根据记录内容的不同，`RREC`可以分为两类：物理`RREC`和逻辑`RREC`。

物理`RREC`的内容包括：修改的数据页、页内偏移、修改类型、修改动作的内容，以及修改内容的长度等信息。

逻辑`RREC`是`DM7`为数据守护新增加的记录类型，主要是为了解决重做`REDO`日志与用户访问备数据库之间的并发冲突，以及`DDL`导致的主备数据库字典缓存不匹配问题。逻辑`RREC`类型包括：事务启动、事务提交、事务回滚、字典封锁、事务封锁、B树封锁、字典淘汰等。虽然这些操作本身不会修改物理数据页，但是主数据库仍然忠实地记录了这些操作，生成相应的逻辑`RREC`记录。备数据库解析到逻辑`RREC`记录时，根据记录内容，生成相应的事务，封锁对应的数据库对象，并从字典缓存中淘汰过期的字典对象。

## 1.2 提供的主要功能特性

对`DM7`数据守护系统的用户来说，无需了解数据守护的内部构造与配置甚至是故障处理与恢复，只需要连接到主机进行生产操作，或连接到备机进行报表生成等查询生产操作即可，如图`1.2`所示。

图`1.2 DM7`数据守护

`DM7`数据守护支持应用自动重连，应用配置和使用连接服务名来访问数据库，在主数据库发生故障后，可自动将连接迁移到新的主数据库上。应用用户在主数据库上的操作与对`DM7`单机版的操作没有什么区别。

对于数据守护系统的管理员则要求更多，需要配置与搭建系统、监控系统的运行并处理系统故障。`DM7`数据守护提供的功能包括：

| 􀁺 主备角色切换 | 通过简单的命令即可将主数据库与备数据库的角色互换，且过程中没有任何数据丢失。 |
| --- | --- |
| 􀁺 故障自动切换 | 当主数据库发生故障时，备用数据库自动切换为主数据库，正常的数据库服务不受影响，切换过程很短通常在数秒之内就能完成。 |
| 􀁺 非自动切换 | 备机只作为数据备份用途，主备模式不主动发生改变。用户需要切换模式时可以手动切换。或者主机长时间故障，符合一定条件下用户可以手动将备机接管成主机。 |
| 􀁺 实时备份库 | 通过配置实时备机，提供数据库实时备份功能。 |
| 􀁺 异步备份库 | 通过配置异步备机和定时器，提供数据库异步备份功能。 |
| 􀁺 自动重加入 | 在故障解决后，恢复的数据库系统可以作为备数据库重新加入数据守护系统。这个过程无需用户干预，系统自动同步历史数据。 |
| 􀁺 滚动升级 | 不间断数据库服务的情况下，滚动地对备数据库和主数据库软件进行升级。 |
| 􀁺 实时监控 | 通过监控工具DMWMON，可实时监控主、备数据库的状态和数据同步情况。 |
| 􀁺 活动的备用数据 | 基于独特的字典缓存技术和日志重演技术，备用数据在Open状态下执行数据同步，是真正意义上的热备机；在实现异地容灾的同时，用户可以只读访问备数据库，执行报表生成、数据备份等功能，减轻主机系统的负载，提高资源利用率。 |
