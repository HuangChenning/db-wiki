本章介绍`DM7`数据守护系统的搭建过程，读者在阅读完本章后，可以选择一个适合应用的数据守护解决方案，并搭建数据守护系统。

本章主要内容包括：

- 数据守护方案选择
- 数据守护系统搭建实例
- 小结

## 3.1 数据守护方案选择

搭建`DM7`数据守护环境，有以下几种方案选择，用户应根据应用系统的实际情况选择合适的方案。

- 只配置主机和实时备机

主机和实时备机加上各自的守护进程已经构成了一个完整的数据守护系统，能够完成数据守护系统的实时备份库、主备角色切换、故障自动切换、非自动切换、自动重加入等数据守护系统的基本功能，满足应用系统对数据安全和高可用性的要求。

- 配置主机、实时备机和最多8个异步备机

如果应用系统的数据库规模很大，只有一个实时备机的情况下性能可能会受到影响，无法分担更多的任务，若应用的统计报表等查询操作对数据的实时性要求不是很严格，则可以配置多个异步备机用于分担负载，提高系统系能。

- 只配置主机和最多8个异步备机

如果只配置主机和异步备机，严格来说这个系统并不算真正的数据守护系统，因为并不具备主备角色切换的功能，也就不能满足高可用的需求。不过主机配备异步备机可以达到给主数据库进行异步备份的效果，在一些特定的应用中也是有使用意义的。

配置异步备机时，如果有实时备机，需要在主机和实时备机上都配置定时器，以便备机切换为主机时可以继续向异步备机发送日志；如果没有实时备机，则只需要配置主机的定时器，定时触发主机发送归档日志到异步备机上，实现异步备机与主机的数据同步。

主备系统如果部署在同一个局域网内，守护进程和监视器可以使用`UDP`广播、组播或`TCP`通信方式，局域网内的组播方式不要求支持相关组播协议。如果跨网段配置，可以使用`UDP`组播或`TCP`方式，组播方式要求连接不同网段的路由器、交换机等设备必须能够支持且打开相关组播协议，因此建议使用`TCP`方式部署。

## 3.2 一个数据守护系统的搭建实例

为了让读者更加直观地理解`DM7`数据守护方案，在本节中我们将以一个实例来说明如何配置一个完整的数据守护系统的过程，配置方案为一个主机、一个实时备机、一个异步备机以及一个监视器，配置步骤中会对异步备机配置项进行说明，如果不需要异步备机，相关的配置也不需要做。

本节介绍的所有操作步骤都为纯手工操作，第五章将会介绍使用`DM7`部署管理工具搭建数据守护系统的用法。使用部署管理工具可以极大简化搭建流程，不过阅读本节可让读者更加深入了解数据守护系统的工作机制，有利于后续对数据守护系统进行管理与故障处理。

### 3.2.2 数据准备

配置数据守护之前，必须先同步主备机数据，确保两者保持完全一致。主数据库可以是新初始化的数据，也可以是正在生产、使用中的数据。可以通过两种方式初始化同步主备机数据：数据文件拷贝以及备份还原方式。

不能使用分别初始化库的方法，因为：

- 每个库都有一个永久魔数（`permenant_magic`），主备机传送日志时会判断这个值是否一样，确保来自同一个库，不同的库传送不了日志；
- 由于`dminit`初始化数据库时，会生成随机密钥用于加密，每次生成的密钥都不相同，备机无法解析采用主机密钥加密的数据。

需要注意的是，如果主数据库是新初始化的库，需要先正常启动并正常退出，然后再使用数据文件拷贝或者备份还原方式准备备机数据。

- 数据文件拷贝

可以通过拷贝数据文件的方式实现主备数据库的同步。具体步骤包括：

1. 正常关闭数据库；
2. 严格按照数据文件在主机上的分布，拷贝数据文件到备机的对应目录；如果数据文件统一存放在一个目录下，则直接拷贝整个目录即可。
- 备份还原方式

用户也可以通过脱机备份、脱机还原的方式同步主备机数据，更详细的说明可以参考`DM7`备份还原的相关文档。具体步骤包括：

1. 正常关闭数据库；
2. 进行脱机备份；

```
./dmrman CTLSTMT="BACKUP DATABASE '/dm7/data/DAMENG/dm.ini' FULL TO BACKUP_FILE1 BACKUPSET '/dm7/data/BACKUP_FILE_01'"
```

3. 拷贝备份文件到备机；
4. 执行脱机数据库还原与恢复。

```
./dmrman CTLSTMT="RESTORE DATABASE '/dm7/data/DAMENG/dm.ini' FROM BACKUPSET '/dm7/data/BACKUP_FILE_01'"
./dmrman CTLSTMT="RECOVER DATABASE '/dm7/data/DAMENG/dm.ini' FROM BACKUPSET '/dm7/data/BACKUP_FILE_01'"
```

- 检查数据一致性

完成主备数据库的同步后，用户可以通过查询主备数据库的`LSN`值和永久魔数来检查主备数据库的数据一致性。

切换到主机`DW_P`的执行码目录`/dm7/bin`，以`mount`方式启动数据库

```
./dmserver /dm7/data/DAMENG/dm.ini mount
```

切换到备机`DW_S`的执行码目录`/dm7/bin`，以`mount`方式启动数据库

```
./dmserver /dm7/data/DAMENG/dm.ini mount
```

切换到异步备机`DW_ASYNC`的执行码目录`/dm7/bin`，以`mount`方式启动数据库

```
./dmserver /dm7/data/DAMENG/dm.ini mount
```

启动命令行工具`disql`，登录主数据库查询`LSN`值

```
SQL>SELECT FILE_LSN, CUR_LSN FROM V$RLOG;
行号 FILE_LSN CUR_LSN
-------- ------------------ --------------------
1 10250 10250
```

启动命令行工具`disql`，登录备数据库查询`LSN`值

```
SQL>SELECT FILE_LSN, CUR_LSN FROM V$RLOG;
行号 FILE_LSN CUR_LSN
-------- ------------------ --------------------
1 10250 10250
```

启动命令行工具`disql`，登录异步备机数据库查询`LSN`值

```
SQL>SELECT FILE_LSN, CUR_LSN FROM V$RLOG;
行号 FILE_LSN CUR_LSN
-------- ------------------ --------------------
1 10250 10250
```

可以看到主备数据库的`FILE_LSN`和`CUR_LSN`值相同，可以确保主备数据库的数据完全一致。

继续在连接主数据库、备数据库和异备数据库的`disql`中查询各数据库的永久魔数，确保一致。

```
SQL>SELECT PERMANENT_MAGIC;
行号 PERMANENT_MAGIC
---------- ---------------
1 1385101984
```

正常关闭主备数据库，继续配置数据守护。

### 3.2.3 配置主数据库

配置主数据库的过程包括修改主数据库的配置文件`dm.ini`、`dmmal.ini`、`dmarch.ini`和设置数据库`OGUID`值，因为有异步备机，还需要配置`dmtimer.ini`。监控主数据库的守护进程与主数据库都在`DW_P`上，因此对于主数据库上守护进程的`dmwatch.ini`的配置也一并介绍，所有配置文件都位于主机的`/dm7/data/DAMENG`目录下。

- 配置`dm.ini`

在`DW_P`机器上配置主数据库实例名为`DM1`，将`dm.ini`相关参数修改如下：

```
INSTANCE_NAME = DM1
PORT_NUM = 5236
DW_UDP_PORT = 5243
INST_UDP_PORT = 5253
MAIL_INI = 1
ARCH_INI = 1
TIMER_INI = 1 #有异步备机时需要置为1
HA_INST_CHECK_FLAG = 1
- 配置dmmal.ini
```

配置`MAL`系统，主备数据库的`dmmal.ini`配置完全一致，`MAL_HOST`使用内部网络`IP`，`MAL_PORT`与`dm.ini`中`PORT_NUM`使用不同的端口值，配置如下：

```
MAL_CHECK_INTERVAL = 5
MAL_CONN_FAIL_INTERVAL = 5
[MAL_INST1]
MAL_INST_NAME = DM1
MAL_HOST = 192.168.0.141
MAL_PORT = 5337
MAL_INST_HOST = 192.168.1.131
MAL_INST_PORT = 5236
[MAL_INST2]
MAL_INST_NAME = DM2
MAL_HOST = 192.168.0.142
MAL_PORT = 5337
MAL_INST_HOST = 192.168.1.132
MAL_INST_PORT = 5236
```

#异步备机MAL配置项

```
[MAL_INST3]
MAL_INST_NAME = DM3
MAL_HOST = 192.168.0.143
MAL_PORT = 5337
MAL_INST_HOST = 192.168.1.133
MAL_INST_PORT = 5236
- 配置dmarch.ini
```

修改`dmarch.ini`，配置本地归档和实时归档，实时归档的`ARCH_DEST`为备数据库实例名。因为有异步备机，还需要配置异步归档，异步归档的`ARCH_DEST`为异步备机数据库实例名、`ARCH_TIMER_NAME`为定时器名称。配置如下：

```
[ARCHIVE_REALTIME]
ARCH_TYPE = REALTIME
ARCH_DEST = DM2
```

#异步归档配置项

```
[ARCHIVE_ASYNC]
ARCH_TYPE = ASYNC
ARCH_DEST = DM3
ARCH_TIMER_NAME = DW_TIMER
[ARCHIVE_LOCAL1]
ARCH_TYPE = LOCAL
ARCH_DEST = /dm7/data/DAMENG
ARCH_FILE_SIZE = 128 #单位Mb
ARCH_SPACE_LIMIT = 0 #单位Mb，0表示无限制，范围1024~4294967294M
- 配置dmtimer.ini
```

如果有异步备机，则需要在主机上配置`dmtimer.ini`，用于定时触发主机发送归档日志到异步备机。本例中我们将定时器配置为每天`00:00:00`触发主机发送归档日志到异步备机，用户可以根据应用实际情况调整。配置如下：

```
[DW_TIMER]
TYPE = 2
FREQ_MONTH_WEEK_INTERVAL = 1
FREQ_SUB_INTERVAL = 0
FREQ_MINUTE_INTERVAL = 0
START_TIME = 00:00:00
END_TIME = 00:00:00.1047296
DURING_START_DATE = 2014-02-11 17:36:09
DURING_END_DATE = 9999-12-31 23:59:59
NO_END_DATE_FLAG = 1
DESCRIBE = DW TIMER
IS_VALID = 1
- 配置dmwatch.ini
```

配置`dmwatch.ini`对主数据库的守护进程进行设置，守护进程之间以及守护进程和监视器之间的通信可以选择`TCP`或`UDP`方式，下面分别进行说明。

`1. UDP`广播配置方式

使用`UPD`广播通信方式时，需要注意：

- `DW_BRO_ADDR`根据`dmmal.ini`中的`MAL_HOST`配置项计算得出
- `DW_UDP_PORT`配置项与`dm.ini`的`DW_UDP_PORT`配置项保持一致
- `INST_UDP_PORT`配置项与`dm.ini`的`INST_UDP_PORT`配置项保持一致

具体配置如下：

```
[GROUP_A]
DW_BRO_ADDR = 192.168.0.255
DW_UDP_PORT = 5243
DW_MODE = 1
DW_INST_ERROR_TIME = 5
DW_FAR_ERROR_TIME = 0
DW_MON_CONFIRM = 0
DW_DM_INI = /dm7/data/DAMENG/dm.ini
INST_OGUID = 82379
INST_NAME = DM1
INST_SERVICE_IP = 192.168.1.131#实例对外服务IP
INST_UDP_PORT = 5253
INST_STARTUP_CMD = /dm7/bin/dmserver /dm7/data/DAMENG/dm.ini
```

`INST_STARTUP_MODE = 1 #0:` 服务方式启动； 1：控制台方式启动

```
INST_AUTO_RESTART = 1
```

`2. UDP`组播配置方式

使用`UPD`组播通信方式应注意：

- `DW_BRO_ADDR`取值范围为`224.0.1.0--238.255.255.255`，同一守护系统中组播地址需要一致
- `DW_UDP_PORT`配置项与`dm.ini`的`DW_UDP_PORT`配置项保持一致
- `INST_UDP_PORT`配置项与`dm.ini`的`INST_UDP_PORT`配置项保持一致

具体配置如下：

```
[GROUP_A]
DW_UDP_TYPE = 1 #(默认0，广播，1组播）
DW_UDP_TTL = 64
DW_BRO_ADDR = 234.1.1.1#当为组播时，组播地址(224.0.1.0--238.255.255.255)
DW_UDP_PORT = 5243
DW_MODE = 1
DW_INST_ERROR_TIME = 5
DW_FAR_ERROR_TIME = 0
DW_MON_CONFIRM = 0
DW_DM_INI = /dm7/data/DAMENG/dm.ini
INST_OGUID = 82379
INST_NAME = DM1
INST_SERVICE_IP = 192.168.1.131#实例对外服务IP
INST_UDP_PORT = 5253
INST_STARTUP_CMD = /dm7/bin/dmserver /dm7/data/DAMENG/dm.ini
```

`INST_STARTUP_MODE = 1 #0:` 服务方式启动； 1：控制台方式启动

```
INST_AUTO_RESTART = 1
```

`3. TCP`配置方式

使用`TCP`配置方式时，通过`DW_TCP_PORT`指定`dmwatch`的`tcp`端口。`Dmwatch`将根据`DW_MAL_INI`和`DW_ARCH_INI`指定的`dmmal.ini`和`dmarch.ini`配置文件获取远程备数据库和异备数据库的守护进程所在的`IP`地址。将`DW_ARCH_TYPE`指定归档类型为实时归档。

由于实例和守护进程之间总是以`UDP`方式通信，因此`TCP`方式下还需要设置两个`UDP`端口，无需设置广播地址。

```
[GROUP_A]
DW_TCP_PORT = 5263
DW_MAL_INI = /dm7/data/DAMENG/dmmal.ini
DW_ARCH_INI = /dm7/data/DAMENG/dmarch.ini
DW_ARCH_TYPE = REALTIME
DW_UDP_PORT = 5243
DW_MODE = 1
DW_INST_ERROR_TIME = 5
DW_FAR_ERROR_TIME = 0
DW_MON_CONFIRM = 0
DW_DM_INI = /dm7/data/DAMENG/dm.ini
INST_OGUID = 82379
INST_NAME = DM1
INST_SERVICE_IP = 192.168.1.131#实例对外服务IP
INST_UDP_PORT = 5253
INST_STARTUP_CMD = /dm7/bin/dmserver /dm7/data/DAMENG/dm.ini
```

`INST_STARTUP_MODE = 1 #0:` 服务方式启动； 1：控制台方式启动

```
INST_AUTO_RESTART = 1
```

- 启动主数据库

现在，我们可以以`Mount`方式启动主数据库了。

```
./dmserver /dm7/data/DAMENG/dm.ini mount
```

注意，一定要以`Mount`方式启动数据库，否则系统启动时会重构回滚表空间，生成`REDO`日志；并且，启动后应用可能连接到数据库进行操作，破坏主备数据库的一致性。数据守护配置结束后，守护进程会自动`OPEN`数据库。

- 设置`OGUID`

为主数据库设置数据守护唯一标识码`OGUID`。启动命令行工具`disql`，登录主数据库，本例中应设置为与`dmwatch.ini`中`INST_OGUID`相同的82379。

```
SQL>sp_set_oguid(82379);
```

- 修改数据库模式

在连接主数据库的`disql`中执行下面的语句，将数据库模式修改为`Primary`。

```
SQL>ALTER DATABASE PRIMARY;
```

经过如上这些步骤，我们就完成了主数据库的配置，下面开始配置备数据库。

### 3.2.4 配置备数据库

配置备数据库的过程包括修改备数据库的配置文件`dm.ini`、`dmmal.ini`、`dmarch.ini`和设置数据库`OGUID`值；因为有异步备机，实时备机上也需要配置`dmtimer.ini`，以便备机切换为主机时可以继续向异步备机发送日志。

监控备数据库的守护进程与备数据库都在`DW_S`上，因此对于备数据库上守护进程的`dmwatch.ini`的配置也一并介绍，所有配置文件都位于备机的`/dm7/data/DAMENG`目录下。

- 配置`dm.ini`

在`DW_S`机器上配置主数据库实例名为`DM2`，将`dm.ini`相关参数修改如下：

```
INSTANCE_NAME = DM2
PORT_NUM = 5236
DW_UDP_PORT = 5243
INST_UDP_PORT = 5253
MAIL_INI = 1
ARCH_INI = 1
TIMER_INI = 1 #有异步备机时需要置为1
HA_INST_CHECK_FLAG = 1
- 配置dmmal.ini
```

备机的`dmmal.ini`配置文件与主机的`dmmal.ini`完全一致，可直接从主机拷贝过来使用。

```
- 配置dmarch.ini
```

修改`dmarch.ini`，配置本地归档和实时归档，实时归档的`ARCH_DEST`为主数据库实例名。因为有异步备机，还需要配置异步归档，异步归档的`ARCH_DEST`为异步备机数据库实例名、`ARCH_TIMER_NAME`为定时器名称。

之所以要为备机配置实时归档和异步归档，是为了在发生主备切换时，备数据库切换为主数据库后能正常向备数据库和异备数据库发送`REDO`日志。当备数据库正常运行没有切换为主数据库时，实时归档和异步归档的配置并没有发生作用。

```
[ARCHIVE_REALTIME]
ARCH_TYPE = REALTIME
ARCH_DEST = DM1
```

### 3.2.5 配置异备数据库

为了完整示例`DM7`数据守护方案的大家，我们的实例中包含了一个异备数据库。如果用户应用中不需要配置异备数据库，可以跳过此步骤，之前配置主数据库和备数据库的步骤中的与异备数据库相关的配置也不需要做。

### 3.2.8 启动守护进程

启动主机`DW_P`上的守护进程。

```

```

```
./dmwatch /dm7/data/DAMENG/dmwatch.ini
```

启动异步备机`DW_ASYNC`上的守护进程。

```
./dmwatch /dm7/data/DAMENG/dmwatch.ini
```

守护进程启动后，进入`Startup`状态，此时主备数据库都处于`Mount`状态。守护进程开始广播自身和其监控数据库的状态信息，结合自身信息和远程守护进程的广播信息，守护进程先将备数据库切换为`Open`状态，再将主数据库切换为`Open`状态，然后守护进程自身进入`Open`状态。

至此，`DM7`数据守护系统搭建完毕，用户可以登录主数据库执行正常的数据库操作，也可以登录备数据库执行数据查询。`DM7`数据守护系统将为用户提供完善的数据保护和高可用性特性。

### 3.2.9 注册服务

如果想让`dmserver`和`dmwatch`开机自启动，需要手动注册服务。手动注册服务方式如下，注意以下步骤必须以`root`用户进行。

1. 复制服务文件`dmserverd`

```
cp /opt/dmdbms/bin/dmserverd /etc/rc.d/init.d/DmServiceDMSERVER
2. 修改服务文件DmServiceDMSERVER
修改DmServiceDMSERVER
svc_prog=DmServiceDMSERVER
model=open
path=INI路径
```

3. 修改启动服务的等级连接

```
ln -s /etc/rc.d/init.d/DmServiceDMSERVER /etc/rc.d/rc0.d/K02DmServiceDMSERVER
ln -s /etc/rc.d/init.d/DmServiceDMSERVER /etc/rc.d/rc2.d/S98DmServiceDMSERVER
ln -s /etc/rc.d/init.d/DmServiceDMSERVER /etc/rc.d/rc3.d/S98DmServiceDMSERVER
ln -s /etc/rc.d/init.d/DmServiceDMSERVER /etc/rc.d/rc5.d/S98DmServiceDMSERVER
ln -s /etc/rc.d/init.d/DmServiceDMSERVER /etc/rc.d/rc6.d/K02DmServiceDMSERVER
```

把`dmwatch`的服务也同样修改对应位置并注册。之后重启机器时，就会自动启动`dmserver`和`dmwatch`了。

### 3.2.11 退出数据守护系统

退出守护系统时，必须按照一定的顺序来关闭守护进程和数据库实例。如果退出守护进程或数据库实例的顺序不对，可能会引起主备模式的切换，或者主备数据的不一致。

退出数据守护系统的方法有两个：

1. 可以通过监视器命令`INST EXIT ALL`安全退出系统，命令执行成功后，守护进程并没有退出，只是状态切换为`SHUTDOWN`状态，以免再将服务拉起。此命令只负责主数据库及其对应守护进程和备数据库及其对应守护进程的处理，并不对异步备机进行处理，用户可之后手动将异步备机退出。

2. 如果使用手动方式退出守护系统，请严格按照以下顺序：

`a)` 关闭备机的守护进程

`b)` 关闭主机的守护进程

`c)` 关闭主机实例

`d)` 关闭备机实例

a比b先做是为了防止在自动切换模式下，备机会自动切换成主机；c比d先做是为了防止主机还存在客户端连接有数据操作的情况下挂起。因为在`INST_AUTO_RESTART`设置为1时，实例关闭后又会被守护进程拉起，所以守护进程比实例先关闭。

## 3.3 小结

本章详细描述了`DM7`数据守护系统的搭建，从如何选择方案到具体的搭建过程以及最后的退出系统。

`3.2`节详细描述了搭建一个完整的`DM7`数据守护系统的全过程，用户按文档描述从`3.2.1`节到`3.2.8`节顺序操作，就能搭建成功了。

文档为了描述清晰，遵循了一定的顺序，用户在搭建时，主/备数据库，主/备数据库对应的守护进程的启动顺序并没有规定，用户可以随意。如果先启动了守护进程而没有启动对应的数据库，若`dmwatch.ini`中的`INST_AUTO_RESTART`配置为0，守护进程会处于`STARTUP`状态直至数据库都启动后守护系统状态正常了转为`OPEN`状态；若`INST_AUTO_RESTART`配置为1，则守护进程会自动启动对应的数据库服务器。

如果用户选择手动退出数据守护系统，则必须要遵循`3.2.10`中描述的退出顺序，否则可能造成守护系统混乱或不可用的严重后果。
