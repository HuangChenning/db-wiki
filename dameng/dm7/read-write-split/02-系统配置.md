## 配置文件

读写分离系统涉及到的配置文件有`dm.ini`、`dmmal.ini`、`dmarch.ini`、`dmrww.ini`、

```
dmrwm.ini。
```

`dm.ini`和`dmmal.ini`的配置和守护进程中的配置一致。

`dmrww.ini`中配置实例相关的信息及端口。

`dmrwm.ini`中配置监视器的端口、组号等信息。

`dmarch.ini`中除了配置本地归档外，需要配置到其他所有实例的即时归档，以便即时备库切换为主库后，可以正常向其他实例发送即时归档。另外`ARCH_WAIT_APPLY`参数值都要一致。

参数说明：

```
RWW_MODE：
```

自动或非自动模式下，`dmrww`检查本地实例满足`open`条件时都会执行自动`open`操作。

自动模式下，主库正常时，`dmrww`检测到故障备库后会执行自动恢复，非自动模式下需要在`dmrwm`端手动执行`recover`命令恢复备库。

被接管后的故障主库的恢复，都需要通过`dmrwm`的`recover`命令手动恢复。

注意：

对于备库来说，这里的恢复是指主备库之间有`lsn`差值，需要主库同步归档日志到备库重做，直到备库`lsn`和主库一致，然后修改备库即时归档为`VALID`状态的过程。

对于主库来说，这里的恢复是指将主库作为备库重加入的过程，包括补齐和新主库之间的`lsn`差值。

实例故障后，如果`INST_AUTO_RESTART`配置为1，会将实例重新拉起，但如果主备库之间存在`lsn`差值，在自动模式下，`dmrww`会自动执行这个恢复过程。

守护进程通信方式说明：

读写分离系统中，守护进程`(dmrww)`和本地实例、远程守护进程`(dmrww)`、监视器之间都有通信，其中守护进程和本地实例之间使用`UDP`方式定向发送消息，守护进程之间、守护进程和监视器之间支持`TCP`和`UDP`两种通信方式， 其中`UDP`方式支持广播和组播配置，广播方式需要守护系统部署在同一个局域网内，组播方式和`TCP`方式同时支持单个局域网和跨网段部署。

`TCP`及`UDP`相关的配置参数请参考`dmrww.ini`配置表格说明，如果同时配置有`TCP`和`UDP`参数，则选择`TCP`方式进行通信。守护进程之间、以及守护进程和监视器之间的通信方式需要保持一致，都使用`TCP`或都使用`UDP`方式，否则读写分离系统无法正常使用。

组播配置说明：

系统支持`UDP`组播配置方式，允许跨网段搭建，`UDP`组播方式条件比较严格，注意事项如下：

1.单个局域网内支持组播方式配置，不需要支持组播协议。

2.跨网段配置时，连接不同网段的路由器、交换机等设备必须能够支持组播协议，并打开相关组播协议。

3.组播组内的主库如果没有组播路由，则需要添加组播路由到路由表中，且需要保证添加组播路由时绑定的网卡设备`IP`地址协议和组内其他主库一致，都使用`IPV4`或`IPV6`协议。

添加组播路由命令（不同操作系统命令格式可能不同，需要根据实际情况调整）：

a. 操作系统Linux localhost.144 2.6.32-220.el6.x86_64，添加路由命令：

```
route add -net 224.0.0.0 netmask 240.0.0.0 dev eth0
```

该命令将D类组播地址224.0.0.0 加入到路由表中，子网掩码240.0.0.0，绑定网卡设备eth0，即组播消息通过设备eth0 发送和接收，同一个多播组中绑定的设备支持的IP 协议需要一致。

此处添加的是动态路由，系统重启后需要重新添加，可以将此命令添加到/etc/rc.local文件，系统启动后自动执行。

b. 操作系统AIX 7.1-64，添加路由命令：

```
route add -net 224.0.0.0 192.168.0.196 -if en0
```

该命令将D类组播地址224.0.0.0 加入到路由表中，网关地址192.168.0.196，绑定网卡设备en0，即组播消息通过设备en0 发送和接收。

此处添加的是动态路由，系统重启后需要重新添加，AIX 可以通过自带的smit 工具，使用smit mkroute 命令进入配置界面，增加为静态路由。

查看路由表命令：

netstat –rn

```
Kernel IP routing table

224.0.0.0       0.0.0.0         240.0.0.0       U         0 0          0    eth0
```

### dmrwm.ini

表2 dmrwm.ini 配置项配置项配置含义RWM_UDP_TYPE UDP 通信方式，0 表示广播方式，1 表示组播方式，默认为0 RWM_UDP_TTL UDP 组播方式下的数据包生存期，数据包传送时最大可经过的路由器个数，取值范围为1 到128，默认为3。

RWM_BRO_ADDR UDP 广播或组播地址，与dmrww.ini 中RWW_BRO_ADDR 保持一致RWM_UDP_PORT UDP 广播端口，与dmrww.ini 中RWW_UDP_PORT 保持一致RWM_INST_OGUID 数据守护唯一标识码，与dmrww.ini 中的INST_OGUID 保持一致RWM_GROUP_NAME 守护进程组名，与dmrww.ini 中的守护进程组名保持一致RWM_CTL_PATH 控制文件路径，存放即时备库切换为主库时的相关信息RWM_RWW_TCP_PORT `TCP`方式下，连接远程`dmrww`的`TCP`端口，和`dmrww.ini`中的

```
RWW_TCP_PORT 保持一致
```

RWM_RWW_IP `TCP`方式下，远程守护进程`(dmrww)`地址，和`dmmal.ini`中的`MAL_HOST`保持一致，该配置项最多允许配置9 个（主库和8 个即时备库），不允许有重复值。

RWM_LOG_PATH 日志文件路径，相关说明请参考下面的注意事项。

日志文件命名方式为 “dmrwm_端口号_年月日时分秒.log”，例如“dmrwm_55681_20150418230523.log”RWM_LOG_INTERVAL 自动记录系统状态信息到日志文件的时间间隔，取值0,1，或(5~3600)，单位秒，0 表示不记录任何日志，1 表示只记录监视器正常接收到的消息，5~3600 表示除了记录监视器正常接收消息外，每隔指定的间隔另外记录系统信息到日志文件中，默认值为1。

RWM_LOG_FILE_SIZE 单个日志文件大小，范围16~2048，单位为M，默认值为64，达到最大值后，会自动生成并切换到新的日志文件中，如果达到设定的总空间限制，会自动删除创建时间最早的日志文件。

RWM_LOG_SPACE_LIMIT 日志总空间大小，取值0 或者256~4096，单位为M，默认值为0，表示没有空间限制。

控制文件说明：

其中`dmrwm`的控制文件记录备库接管主库时的相关信息，包括新主库名、故障主库名以及备库接管主库时的`lsn`这三项。

在主库恢复做为备库重加入时，需要先查找控制文件，如果没有找到该主库的接管信息，则不允许加入。如果找到，则比较其`lsn`是否大于切换当时的`lsn`，若大于则不允许主库加入，在满足条件加入成功后，控制文件中对应的接管记录会被删除。

如果发生多次备库接管，比如主库A故障，备库B接管为主库后又发生故障，又选用备库C接管，则控制文件中会依次记录B、C接管时的信息，在主库A、B重新加入时依次查找对应的记录，加入成功后删除相关记录。

该控制文件在执行接管命令的`dmrwm`所在机器上生成，生成路径为`RWM_CTL_PATH`配置的参数值，如果用户在多个机器上配置有监视器并执行过接管命令，则各自都会生成对应的控制文件，需要在对应机器上对被接管的主库执行恢复，否则会因为找不到接管信息不允许故障主库重加入。

也可以多个监视器共用同一个控制文件，注意在执行切换前，需要先拷贝到本地控制文件路径下，其他命令的执行则没有此限制。建议执行备库接管和主库恢复命令都在同一个监视器上执行，就不会受控制文件的限制。

接管说明：

在监视器上执行备库的接管命令时，一定要先确认是主库实例故障而不是内网网卡故障或其他网络问题。如果是内网网络问题，监视器收不到主库消息会误判主库出现故障，此时再执行备库接管，系统中就会出现双主库，老的主库继续在对外提供服务，并且双主库会同时向即时备库发送归档，这种情况下无法保证主备数据的正确性。

日志相关配置说明：

`dmrwm.exe`工具的日志文件路径以`dmrwm.ini`中配置的`RWM_LOG_PATH`为准，如果没有配置则使用`dmrwm.ini`配置文件所在的路径作为日志文件路径。

如果是通过调用接口方式来使用监视器的相关功能时，日志文件路径以`dmrwm_init`接口中指定的`log_path`为准，如果`log_path`参数值为`NULL`或空串，则以`dmrwm.ini`中的`RWM_LOG_PATH`为准，如果两个都没指定，则使用`dmrwm.ini`配置文件所在的路径作为日志文件路径。

```
RWM_LOG_FILE_SIZE 和RWM_LOG_SPACE_LIMIT 的配置不起作用。
```
