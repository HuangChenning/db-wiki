提供dmrwm 工具对读写分离主备系统进行管理，其功能包括启动系统、显示系统信息以及恢复系统故障等。

表`1 dmrwm`命令命令含义`HELP`显示帮助信息`SHOW`显示所有实例信息`SHOW I[NTERVAL] n`每隔n秒自动显示组中所有实例信息Q取消自动显示

```
LOGIN  登录DMRWM
```

`LOGOUT`退出登录`TIP`显示系统当前运行状况`STARTUP ALL`启动所有`dmrww`的监控功能`STOP ALL`停止所有`dmrww`的监控功能`STARTUP`实例名启动指定实例`dmrww`的监控功能`STOP`实例名停止指定实例`dmrww`的监控功能`INST STARTUP ALL`启动所有实例`INST EXIT ALL`退出所有实例`INST STARTUP`实例名启动指定的实例`INST EXIT`实例名退出指定的实例

`OPEN ALL` `open`所有实例

`OPEN`实例名`open`指定的实例`SWITCHOVER`实例名切换指定的实例为主库`RECOVER`实例名恢复指定的实例`CHOOSE`选择可以接管主库的备库`TAKEOVER USE`实例名使用指定的实例接管故障主库`TAKEOVER FORCE USE`实例名使用指定的实例强制接管故障主库`EXIT`退出工具

命令参数:

```
dmrwm  [ini_path | help]
```

示例：

./dmrwm /dm7data/dmrwm.ini

注意：需要指定正确的dmrwm.ini 路径，工具才能正常启动。

## 查看实例状态

> SHOW：

显示系统中所有实例信息SHOW I[NTERVAL]：

每隔n秒自动显示组中所有实例信息，n取值 5~3600，单位为秒。

控制台有命令输入时会取新自动显示。

> Q：

取消自动显示

## 登录DMRWM

LOGIN:监视器执行以下命令时都需要先登录，用户名/密码和服务器登录口令一致，且必须有DBA 权限。

```
1. STOP ALL/STOP 实例名
2. INST EXIT ALL/INST EXIT 实例名
3. OPEN ALL/OPEN 实例名
4. SWITCHOVER/RECOVER/TAKEOVER USE 实例名
```

其他命令不需要登录监视器。

LOGIN 命令默认使用SYSDBA/SYSDBA 作为登录口令，可以直接回车，不需要显示输入。

## 退出登录

LOGOUT:退出登录监视器。

## 停止/启动所有监控

1. STOP  ALL

（1）停止所有dmrww 的监控功能（2）如果某个dmrww 已经是SHUTDOWN 状态，会跳过继续执行

2. STARTUP  ALL

（1）启动所有dmrww 的监控功能（2）如果某个dmrww 已经是STARTUP 或OPEN 状态，会跳过继续执行

## 停止/启动指定实例的监控

1. STOP 实例名

停止指定实例dmrww 的监控功能

2. STARTUP 实例名

启动指定实例dmrww 的监控功能

## 启动所有实例

INST STARTUP ALL:启动所有实例，如果dmrww 已经配置有自动重启，则命令会执行失败，等待dmrww自动将实例拉起。

如果某个实例已经处于运行状态，则跳过继续启动其他实例，主备库启动没有先后顺序，主库等所有备库OPEN 后自动OPEN。

## 启动指定的实例

> INST STARTUP 实例名：

启动指定的实例，如果dmrww 已经配置有自动重启，则命令会执行失败，等待dmrww自动将实例拉起。

要求实例处于SHUTDOWN 状态，dmrww 为STARTUP 或SHUTDOWN 状态。

## 退出所有实例

INST EXIT ALL:退出系统中的所有实例，为防止退出后dmrww 又将实例自动拉起， dmrww 会切换为SHUTDOWN 状态，dmrww 不会退出，如果命令执行失败，会将dmrww 重新设置为STARTUP状态。

该命令用于系统正常运行情况下的正常退出，执行命令前所有守护进程和实例都必须处于OPEN 状态。

## 退出指定的实例

> INST EXIT 实例名：

退出指定的实例，为防止退出后dmrww 又将实例自动拉起， dmrww 会切换为SHUTDOWN 状态，dmrww 不会退出，如果命令执行失败，会将dmrww 重新设置为STARTUP状态。

该命令执行时，要求实例正常运行，实例dmrww 状态为STARTUP 或OPEN，否则不允许退出实例。

## OPEN 实例

1. OPEN ALL

（1） open 所有实例，执行顺序为先open 所有备库，再open 主库（2）系统中如果已存在open 状态的实例，open all 会跳过继续open 其他实例

2. OPEN + 实例名

（1） open 指定的实例，主库故障重启，仍然作为主库重加入时，可以直接open。

（2）备库故障重启，也可以直接open，如果lsn 小于主库，即时归档状态会转为无效状态，需要使用RECOVER 命令执行恢复。

注意：这两个命令一般不需要使用。

（1）对于备库，mount 方式启动后，dmrww 会自动执行open 操作。

（2）对于主库，mount 方式启动后，dmrww 根据接收到的备库广播消息来判断是否自动open。

a. 主库需要收到所有备库dmrww 的广播消息，如果备库的dmrww 故障，主库不会自动open。

b. 如果有备库不是standby&open 状态，主库不会自动open如果确实是备库出现故障，且用户可以确认系统中只有一个主库，且主库数据可靠的情况下，可以使用open 命令单独open 主库。

但在情况a下，主库dmrww 会一直保持STARTUP 状态，不允许执行自动或手动恢复操作。

系统中存在多个主库实例时：

（1） 多个mount 状态的primary 实例a. 不允许执行open all b. 允许执行open 操作，只允许open pocnt 计数最大的主库实例（最后一个执行接管操作的主库），其他实例open 会报错“已被接管”。

（2） 多个open 状态的primary 实例会强制shutdown 所有open 状态的主库pocnt 计数：非standby 模式的实例每执行一次open 操作时该计数加1，在没有用户干预的情况下，认为系统中open 次数最多的主库实例为合法主库。

## 恢复实例

> RECOVER + 实例名：

（1）恢复故障主库查找控制文件，判断主库lsn 是否小于接管当时备库的lsn，若符合则作为备库重新加入，否则报错处理。

（2）恢复故障备库通知主库dmrww 修改为recovery 状态，并发送即时归档到备库，备库和主库数据一致后open 备库。

注意：dmrww 在自动守护模式（RWW_MODE=1）下，会自动检测并恢复故障备库，故障主库仍然需要使用recover 命令手动恢复。

## 选择接管备库

> CHOOSE：

监视器选择出可以接管故障主库的即时备库。

注意：这里只选择即时归档状态为VALID 的备库，如果系统中所有备库即时归档都无效，则不允许接管主库，如果要强制接管，则需要使用强制接管命令。

## 接管命令

> TAKEOVER USE + 实例名：

主库故障后，使用指定的备库实例接管为新主库，并记录接管信息到控制文件中。

此命令要求接管用的备库即时归档状态是VALID 有效状态，接管完成后，可能会出现故障主库无法重新加入的情况。

如果主库是在写入本地日志之后，发送即时归档到备库之前故障，备库接管时会比主库少一段日志，在接管完成后，不允许故障主库再加入系统，避免数据被破坏。

注意：使用接管命令时，一定要确认是主库实例故障，而非内网网络问题或网卡故障导致接收不到实例广播消息而出现的误判，否则直接接管可能会造成系统中出现双主库，导致数据被破坏。

## 强制接管命令

> TAKEOVER FORCE USE + 实例名：

主库故障后，允许使用此命令强制接管故障主库，此命令不要求接管用的备库即时归档状态为VALID，但必须是所有备库（监视器收到过消息的）中SLSN 值最大的备库，且处于OPEN状态。

使用此命令需要谨慎，可能会导致以下情况：

如果执行接管的备库即时归档状态是INVALID，则和故障主库之间有日志差，强制接管后，故障主库将无法再重新加入主备系统，需要重新准备数据。

如果接管当时，有LSN 更大的故障备库（监视器没有收到过此故障备库的消息），在接管成功后，该故障备库又重新加入系统，接管后的新主库做了一系列操作后，LSN 比重加入的故障备库大，又再次同步数据过去，则会导致数据被破坏。

注意：使用接管命令时，一定要确认是主库实例故障，而非内网网络问题或网卡故障导致接收不到实例广播消息而出现的误判，否则直接接管可能会造成系统中出现双主库，导致数据被破坏。

## 切换主备库

> SWITCHOVER + 实例名：

主备库正常的情况下，将指定的备库实例切换为新主库，老的主库切换为备库。

注意：执行切换时要求主备库实例都是open 状态，且主备库dmrww 也处于open 状态，否则不允许切换。

如果切换过程中，待切换为主库的备库故障，而原主库已切换为备库模式，switchover 执行失败，导致系统中没有可用主库时，可以通过接管方法，选择一个符合条件的备库接管为新主库。

## 状态检测

> TIP：检测系统当前运行状况。

主要做下面三个方面检查：

（1） 系统中是否存在多个open 状态的主库（2） 系统中主库状态a. 主库实例是否正常（primary&open）b. 主库lsn 是否大于等于备库c. 主库dmrww 状态是否正常（3） 系统中各备库状态a. 备库实例是否正常（standby&open）b. 备库即时归档是否有效c. 备库dmrww 状态是否正常如果检查到存在异常，在rwm 端打印相关提示信息给用户。
