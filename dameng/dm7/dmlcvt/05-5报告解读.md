下面以一个具体的实例来解读四个报告：`rec_info000.txt`、 `page_info000.txt`、`file_info.txt`和`warn_info.txt`。其中，`rec_info000.txt`、 `page_info000.txt`名字中的数字000，会随着文件数量的增加，数字不断变大。

例如，初始化一个数据库，配置归档。创建一张表，在表中插入10000条数据后，使用`dmlcvt`工具对该库的日志文件进行解析。得到如下四个报告，其中`warn_info.txt`报告中，只有操作有误，才会有内容。

`--`使用`dminit`工具初始化库

```
./dminit path=/opt/dmdbms
```

`--`在`DIsql`工具中配置归档

```
ALTER DATABASE MOUNT;
ALTER DATABASE ADD ARCHIVELOG 'DEST=/opt/dmdbms/temp, TYPE = local, FILE_SIZE = 1024, SPACE_LIMIT = 2048';
ALTER DATABASE ARCHIVELOG;
ALTER DATABASE OPEN;
```

`---`在`DIsql`工具中创建一张表，插入10000条数据。

```
drop table t_sagr_01 cascade;
create table t_sagr_01(c1 varchar(100), c2 varchar(100));
begin
for i in 1..10000 loop
insert into t_sagr_01 values('a'||i, 'b'||i);
end loop;
end;
/
```

`--`使用`dmlcvt`工具分析日志

```
./dmlcvt F_TYPE=1 F_PATH=/opt/dmdbms/DAMENG/dm.ctl out_path=/opt/dmdbms/out
```

四个报告详细介绍如下：

## 5.1 file_info.txt

记录日志文件信息，包括：文件的类型、文件的数量、文件绝对路径、日志文件在控制文件中的路径、检查点信息等。该报告信息正是`dmlcvt`工具执行过程中屏幕上打印的信息。

```

/opt/dmdbms/DAMENG/DAMENG02.log

/opt/dmdbms/DAMENG/DAMENG01.log

analyze start time: 2016-01-11 13:21:36 +16:40
analyze end time: 2016-01-11 13:21:38 +16:40
```

## 5.2 page_info000.txt

记录日志页信息，包括：物理事务日志序列号（`ptx_lsn`）、日志页校验值（`rpag_magic`）、日志页使用长度（`rpag_len`）、日志页序号（`rpag_seq`）和页中包含多少个`ptx(ptx_count in page=?)`。用户可以通过`PAGE_INFO`参数来设置，是否要打印日志页信息。

## 5.3 rec_info000.txt

记录物理事务信息和事务对应的记录信息。

报告中的`ptx`是物理事务信息。`ptx`参数值表示（日志页序号、页使用长度、`ptx lsn`）。

报告中的`DWORD`、`BYTE`和`WORD`等是记录的类型宏定义名称缩写。记录类型括号中的参数值如果是5个，则表示（表空间`id`、文件`id`、页号、页内偏移、修改数据长度）；如果参数值只有四个，则表示（表空间`id`、文件`id`、页号、页内偏移）；如果参数值只有三个，则表示（表空间`id`、文件`id`、页号）。

用户可以通过参数`REC_LEVEL`来设置，是打印物理事务信息（`ptx)`，还是事务对应的记录信息。默认是两者都打印。

## 5.4 warn_info.txt

记录操作过程中出现的警告和错误信息。如果操作过程中一直没有出现错误，那么这个报告一直是空的。

例如，指定`F_TYPE=1`，而`F_PATH`没有指定绝对路径，只指定了相对路径。

```
./dmlcvt F_TYPE=1 F_PATH=/opt/DAMENG out_path=/emc_2/temp
```

则会出现错误，`warn_info.txt`中会记录控制文件打开失败错误。

```
ctl file open error! please check input.
```
