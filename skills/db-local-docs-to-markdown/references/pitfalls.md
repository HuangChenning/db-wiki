# 转换时的取舍

## 先 CHM，PDF 补缺

CHM 用 7-Zip 解开，不依赖 `extract_chmLib`。里面每一本是一份 Word HTML：`h1` 是章，`h2` 及以下留在该章正文里。编码按 `gb18030` 读。

Word 把西文标成 Courier、中文标成宋体。只把连续的英文标识、路径和命令收成行内代码或代码块，不要把整段中文收进去。`mso-ascii-font-family` 只说明西文用了 Courier。

提示框经常是两列、左列为空的表，转成引用。`.emz`、`.wmf` 不复制。VML 里的 `png`/`gif`/`jpg` 会抽到 `img/`。

`.hhc` 里有子节点的条目是目录页（技术丛书、技术手册、首页），不要单独成书。`~$` 和 `header.htm` 是 Word 残骸。

## PDF

用 PyMuPDF 的文字层和书签。拆章取最浅一层里、去掉「目录」之后仍至少有两章的那一层。更深的书签变成该章里的标题。

没有书签、或前几页几乎没有文字的 PDF 不要 OCR。脚本会停在这本上。

同一行里的 Courier 片段收成行内代码。整行大部分是 Courier 时收成代码块，所以参数帮助和 `CREATE TABLE` 会进围栏。单字母（例如「B 树」里的 B）不要加反引号。

页眉书名和页脚页码会去掉。前言里的标志表是小图标加文字，图标低于大约 80×36 点就丢掉，文字可能对不齐。这是 PDF 路径的已知缺口，有 CHM 时不要改走 PDF。

## 文件名

部分 PDF、CHM 的文件名是 GBK 被当成 Mac 罗马字符存下来的。`list_docs.py` 会还原显示名。清单里的 `source` 必须仍是磁盘上的真实路径。

## 和在线库的差别

章节 `source` 是仓库内相对路径。PDF 加 `#page=`，CHM 加 `#` 和主题路径。目录链接仍然是相对 Markdown，不写本机绝对路径。
