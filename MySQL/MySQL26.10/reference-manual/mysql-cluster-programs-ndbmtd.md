### 25.5.3 ndbmtd — The NDB Cluster Data Node Daemon (Multi-Threaded)

**ndbmtd** is a multithreaded version of [**ndbd**](mysql-cluster-programs-ndbd.md), the process that is used to handle all the data in tables using the [`NDBCLUSTER`](mysql-cluster.md) storage engine. **ndbmtd** is intended for use on host computers having multiple CPU cores. Except where otherwise noted, **ndbmtd** functions in the same way as [**ndbd**](mysql-cluster-programs-ndbd.md); therefore, in this section, we concentrate on the ways in which **ndbmtd** differs from [**ndbd**](mysql-cluster-programs-ndbd.md), and you should consult [Section 25.5.1, “ndbd — The NDB Cluster Data Node Daemon”](mysql-cluster-programs-ndbd.md), for additional information about running NDB Cluster data nodes that apply to both the single-threaded and multithreaded versions of the data node process.

Command-line options and configuration parameters used with [**ndbd**](mysql-cluster-programs-ndbd.md) also apply to **ndbmtd**. For more information about these options and parameters, see [Section 25.5.1, “ndbd — The NDB Cluster Data Node Daemon”](mysql-cluster-programs-ndbd.md), and [Section 25.4.3.6, “Defining NDB Cluster Data Nodes”](mysql-cluster-ndbd-definition.md), respectively.

**ndbmtd** is also file system-compatible with [**ndbd**](mysql-cluster-programs-ndbd.md). In other words, a data node running [**ndbd**](mysql-cluster-programs-ndbd.md) can be stopped, the binary replaced with **ndbmtd**, and then restarted without any loss of data. (However, when doing this, you must make sure that [`MaxNoOfExecutionThreads`](mysql-cluster-ndbd-definition.md) is set to an appropriate value before restarting the node if you wish for **ndbmtd** to run in multithreaded fashion.) Similarly, an **ndbmtd** binary can be replaced with [**ndbd**](mysql-cluster-programs-ndbd.md) simply by stopping the node and then starting [**ndbd**](mysql-cluster-programs-ndbd.md) in place of the multithreaded binary. It is not necessary when switching between the two to start the data node binary using [`--initial`](mysql-cluster-programs-ndbd.md).

Using **ndbmtd** differs from using [**ndbd**](mysql-cluster-programs-ndbd.md) in two key respects:

1. Because **ndbmtd** runs by default in single-threaded mode (that is, it behaves like [**ndbd**](mysql-cluster-programs-ndbd.md)), you must configure it to use multiple threads. This can be done by setting an appropriate value in the `config.ini` file for the [`MaxNoOfExecutionThreads`](mysql-cluster-ndbd-definition.md) configuration parameter or the [`ThreadConfig`](mysql-cluster-ndbd-definition.md) configuration parameter. Using `MaxNoOfExecutionThreads` is simpler, but `ThreadConfig` offers more flexibility. For more information about these configuration parameters and their use, see [Multi-Threading Configuration Parameters (ndbmtd)](mysql-cluster-ndbd-definition.md).
2. Trace files are generated by critical errors in **ndbmtd** processes in a somewhat different fashion from how these are generated by [**ndbd**](mysql-cluster-programs-ndbd.md) failures. These differences are discussed in more detail in the next few paragraphs.

Like [**ndbd**](mysql-cluster-programs-ndbd.md), **ndbmtd** generates a set of log files which are placed in the directory specified by [`DataDir`](mysql-cluster-ndbd-definition.md) in the `config.ini` configuration file. Except for trace files, these are generated in the same way and have the same names as those generated by [**ndbd**](mysql-cluster-programs-ndbd.md).

In the event of a critical error, **ndbmtd** generates trace files describing what happened just prior to the error' occurrence. These files, which can be found in the data node's [`DataDir`](mysql-cluster-ndbd-definition.md), are useful for analysis of problems by the NDB Cluster Development and Support teams. One trace file is generated for each **ndbmtd** thread. The names of these files have the following pattern:

```svg
ndb_node_id_trace.log.trace_id_tthread_id,
```

In this pattern, *`node_id`* stands for the data node's unique node ID in the cluster, *`trace_id`* is a trace sequence number, and *`thread_id`* is the thread ID. For example, in the event of the failure of an **ndbmtd** process running as an NDB Cluster data node having the node ID 3 and with [`MaxNoOfExecutionThreads`](mysql-cluster-ndbd-definition.md) equal to 4, four trace files are generated in the data node's data directory. If the is the first time this node has failed, then these files are named `ndb_3_trace.log.1_t1`, `ndb_3_trace.log.1_t2`, `ndb_3_trace.log.1_t3`, and `ndb_3_trace.log.1_t4`. Internally, these trace files follow the same format as [**ndbd**](mysql-cluster-programs-ndbd.md) trace files.

The [**ndbd**](mysql-cluster-programs-ndbd.md) exit codes and messages that are generated when a data node process shuts down prematurely are also used by **ndbmtd**. See [Data Node Error Messages](https://dev.mysql.com/doc/ndb-internals/en/ndb-node-error-messages.html), for a listing of these.

Note

It is possible to use [**ndbd**](mysql-cluster-programs-ndbd.md) and **ndbmtd** concurrently on different data nodes in the same NDB Cluster. However, such configurations have not been tested extensively; thus, we cannot recommend doing so in a production setting at this time.
